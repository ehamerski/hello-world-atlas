# Dart · mobile-flutter: Hello, World!

> Part of [Hello World in many languages](../../../README.md) ·
> Language overview: [Dart](../README.md)

## What this is
A Flutter app written in Dart. It shows the text `Hello, World!` on one
screen. The code is one Dart file, `lib/main.dart`, and it is built for
Android: `build.sh` makes an APK, and `run.sh` installs it on an Android
emulator. The same Dart code can also be built for iOS, but iOS is **not
verified** in this folder (see [Platform notes](#platform-notes)).

## Prerequisites
| Tool | Version used (macOS Intel) | Why it is needed |
|---|---|---|
| Flutter SDK | 3.47.9, stable channel (verified 2026-11-12) | Contains the `flutter` command and the Dart SDK that compiles `lib/main.dart`. |
| Java (JDK) | 21.0.8 (Eclipse Temurin) | Android's `sdkmanager`, `avdmanager` and Gradle are Java programs. |
| Android SDK | platform 36, build-tools 36.0.0 | Gradle builds the APK with these; Flutter does not ship them. |
| Android emulator and x86_64 system image | `system-images;android-36;google_apis;x86_64` | The virtual phone that runs the APK. |
| `adb` (platform-tools) | from the Android SDK | Installs the APK on the emulator and reads the app's log. |

`./install.sh` checks each item, and it asks before it downloads or installs
anything. The versions and SHA-256 checksums are pinned in
[`flutter-env.sh`](flutter-env.sh). Flutter's own install steps are at
[docs.flutter.dev/install](https://docs.flutter.dev/install) [1].

## Quick start
```sh
./install.sh   # check / install the Flutter SDK and Android SDK (asks before installing)
./build.sh     # resolve the Dart packages and build build/app/outputs/flutter-apk/app-release.apk
./run.sh       # start the emulator and run the app with `flutter run` (Ctrl+C to stop)
./run.sh --verify   # self-check: start the emulator, install the APK, read the log, stop
```

## Scripts explained
| Script | What it does | Why it is needed |
|---|---|---|
| `install.sh` | Checks Java; installs Flutter 3.47.9 into `~/.local/flutter`; installs the Android command-line tools; installs the SDK packages; creates the `hello-flutter` virtual device. | Each tool is needed once. Downloads are checked against a pinned SHA-256 before they are unpacked. |
| `build.sh` | Runs `flutter pub get`, then `flutter build apk --release`. | `pub get` fetches the packages listed in `pubspec.yaml`. The release build compiles Dart ahead of time (AOT) into native code, which is what an APK ships. |
| `run.sh` | Boots the emulator if needed, then runs `flutter run` (debug build with hot reload). | A phone runs an APK, so the emulator must boot first. `flutter run` also keeps the connection open for hot reload. |
| `run.sh --verify` | Builds the APK if it is missing, installs it with `adb install`, starts `MainActivity`, waits for the log line `Hello, World!` in `logcat`, prints it, and stops what it started. | `scripts/verify-all.sh` needs a script that ends by itself and prints the greeting. The emulator is stopped only if this script started it. |
| `flutter-env.sh` | Sets the Flutter version, the checksums, the SDK folder, the AVD name and the app id. It is sourced, not run. | The three scripts must agree on the same values. |

## Folder structure
```text
mobile-flutter/
├── README.md              this file
├── install.sh             checks / installs Flutter and the Android SDK
├── build.sh               builds the release APK
├── run.sh                 runs the app (or --verify)
├── flutter-env.sh         versions, checksums and paths (sourced)
├── pubspec.yaml           the app's name, version and Dart packages
├── pubspec.lock           the exact package versions that were resolved
├── analysis_options.yaml  lint rules for `dart analyze`
├── lib/main.dart          the whole app (one file)
├── android/               the Android project (Gradle), generated by `flutter create`
└── ios/                   the iOS project (Xcode), generated by `flutter create`; not built here
```
Layout reference: the folders are created by `flutter create`, which the
[Flutter CLI reference](https://docs.flutter.dev/reference/flutter-cli) documents [2].
The [Flutter architectural overview](https://docs.flutter.dev/resources/architectural-overview) [3]
explains how the app code in `lib/` is organized.

## Step-by-step walkthrough
1. `pubspec.yaml` names the app `hello_flutter`, and its only dependency is the
   Flutter SDK itself. Dart packages from pub.dev are not needed for this
   program.
2. `lib/main.dart` imports `package:flutter/material.dart`. In Dart an import
   names a package, not a folder path, as in Java's `import java.util.*`.
3. `main()` is the entry point. It prints `Hello, World!` first, so the line
   reaches `logcat` (the Android log), and then calls `runApp(const HelloApp())`.
4. `HelloApp` is a `StatelessWidget`: a widget that holds no changing state.
   Flutter describes the screen with widgets and draws them itself.
5. `MaterialApp` and `Scaffold` give the Material Design page layout, and
   `Center` puts the `Text` widget in the middle of the screen.
6. `android/app/build.gradle.kts` sets the application id
   (`com.example.hello_flutter`). `run.sh --verify` uses it to start the app.

**Compared with the other Dart folders:** `dart/cli` and `dart/web` run on the
Dart VM with `dart`. Here the same language is compiled for a phone, and the
UI comes from the Flutter framework instead of `print` or `dart:io`.

## Why this toolchain
Flutter is Google's open-source UI toolkit. Its apps are written in Dart, and
one code base can target Android, iOS, the web and desktop [4]. Flutter draws
its widgets with its own rendering engine, which the architectural overview
describes under "Flutter's rendering model" [3]. The Android part of a Flutter app is a Gradle project, and the
deployment guide has a section on its build configuration [5]. The Android
emulator and `adb` are the official tools for running Android apps without a
physical device [6][7].

## Platform notes
| Platform | Status | Notes |
|---|---|---|
| macOS Intel (Android emulator, x86_64) | ✅ verified (2026-11-12) | `install.sh`, `build.sh` and `run.sh --verify` were run on the dev machine (macOS 26, Flutter 3.47.9, Android API 36 emulator). The release build turns Impeller off; see the Android run notes below. |
| macOS Apple Silicon | ⚠️ not verified | `install.sh` pins the Intel archive only. |
| Linux (Debian/Ubuntu) | ⚠️ not verified | No Flutter or Android setup was run on Linux. |
| Windows (Git Bash / WSL) | ⚠️ not verified | Install Flutter and the Android SDK by hand, then run `./build.sh`. |
| iOS (Simulator) | ⚠️ not verified | Not built or run on the dev machine: `build.sh` and `run.sh` build and start the Android app only. The `ios/` folder is the Xcode project that `flutter create` generated. |

**Android run notes (dev machine):** `flutter build apk --release` built the
APK (43.0 MB), and it installed with `adb install`. With Flutter's default
renderer, Impeller, the x86_64 emulator (software GPU, `swiftshader_indirect`)
stopped drawing: the Flutter splash screen stayed up, and once the system UI
showed "System UI isn't responding". `android/app/src/main/AndroidManifest.xml`
therefore sets `io.flutter.embedding.android.EnableImpeller` to `false`, which
falls back to the legacy OpenGL renderer. Flutter's docs describe this opt-out
for Android [8]. With it set, the screen drew `Hello, World!`, shown below.
The setting applies to every device that runs this APK, not only the emulator,
so a real device also uses the legacy renderer until the line is removed. The
Flutter version pinned here is 3.47.9. The docs page cited above is for a newer
release, so the key should be checked again when the pin changes.
